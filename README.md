# Проектная работа "Веб-ларек"

Стек: HTML, SCSS, TS, Vite

Структура проекта:
- src/ — исходные файлы проекта
- src/components/ — папка с JS компонентами
- src/components/base/ — папка с базовым кодом

# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные

#### Сущность товара - IProduct
Сущность товаров, описывается интерфейсом:
`interface IProduct {`
  `id: string;` - id товара
  `description: string;` - описание товара
  `image: string;` - картинка товара
  `title: string;` - заголовок товара
  `category: string;` - к какой категории относится товар
  `price: number | null;` - возможность приобрести и цена товара
`}`

#### Сущность покупатель - IBuyer
Сущность покупателей, описывается интерфейсом:
`interface IBuyer {`
  `payment: TPayment | null;` - способ оплаты
  `email: string;` - email покупателя
  `phone: string;` - телефон покупателя
  `address: string;` - адресс покупателя
`}`

#### Валидация ввода данных - IValidationErrors
Тип хранит ошибки валидации полей покупателя. Каждому полю интерфейса IBuyer может соответствовать строка с текстом ошибки.
`type IValidationErrors = Partial<Record<keyof IBuyer, string>>`

### Модель данных

Каждая модель получает в конструкторе брокер событий `events: IEvents`. Любой метод, изменяющий хранимые данные, после изменения генерирует событие — это позволяет Презентеру узнавать об изменениях в моделях, не опрашивая их вручную, и обновлять представление только тогда, когда данные реально поменялись.

#### Класс "Каталог товаров" Products
Класс хранит в себе:
- массив всех товаров
- товар, выбранный для подробного отображения

Методы:
- сохранение массива товаров полученного в параметрах метода
- получение массива товаров из модели
- получение одного товара по его id
- сохранение товара для подробного отображения
- получение товара для подробного отображения

События:  
`products:changed` - генерируется при сохранении нового массива товаров каталога, передаёт `{ products: IProduct[] }`  
`product:selected` - генерируется при сохранении товара, выбранного для подробного просмотра, передаёт `{ product: IProduct }`

#### Класс "Корзина" ShopList
Класс хранит в себе:
- массив товаров которые покупатель выбрал для покупки

Методы:
- получение массива товаров, которые находятся в корзине
- добавление товара, который был получен в параметре, в массив корзины
- удаление товара, полученного в параметре из массива корзины
- очистка корзины
- получение стоимости всех товаров в корзине
- получение количества товаров в корзине
- проверка наличия товара в корзине по его id, полученного в параметр метода

События:  
`basket:changed` - генерируется при добавлении товара, удалении товара и очистке корзины, передаёт `{ products: IProduct[] }` - актуальный список товаров в корзине

#### Класс "Покупатель" Buyer
Класс хранит в себе:
- вид оплаты
- адресс
- телефон
- email

Методы:
- сохранение данных в модели
- получение всех данных покупателя
- очистка данных покупателя
- валидация данных

События:  
`buyer:changed` - генерируется при сохранении любого поля покупателя (`setPayment`, `setEmail`, `setPhone`, `setAddress`) и при очистке данных (`clearBuyerData`), передаёт `{ buyer: IBuyer }` - актуальные данные покупателя. Метод `validate()` событий не генерирует - он не изменяет данные, а только проверяет их.

Методы:

### Слой представления (View)

Все классы представления наследуются от базового класса `Component` и отвечают за отображение конкретного блока разметки. Ни один класс представления не хранит и не изменяет данные приложения самостоятельно — при любом действии пользователя генерируется событие, которое обрабатывает Презентер.

#### Класс Gallery
Отвечает за отображение каталога товаров на главной странице (`<main class="gallery">`).

Конструктор:  
`constructor(container: HTMLElement)` - принимает DOM-элемент контейнера каталога. Брокер событий не нужен — сама галерея не порождает пользовательских действий, клики обрабатывают вложенные в неё карточки `CardCatalog`.

Методы класса:  
`set items(items: HTMLElement[])` - заменяет содержимое каталога на переданный массив DOM-элементов карточек товаров

#### Класс Header
Отвечает за шапку сайта — логотип и кнопку корзины со счётчиком товаров.

Конструктор:  
`constructor(events: IEvents, container: HTMLElement)` - принимает брокер событий и DOM-элемент шапки.

Поля класса:  
`counterElement: HTMLElement` - элемент счётчика товаров в корзине  
`basketButton: HTMLButtonElement` - кнопка открытия корзины

Методы класса:  
`set counter(value: number)` - записывает переданное значение в счётчик товаров

События:  
`basket:open` - генерируется по клику на кнопку корзины

#### Класс CardBase (абстрактный)
Общий родитель для всех трёх видов карточки товара. Содержит функционал, одинаковый для карточки в каталоге, карточки предпросмотра и строки товара в корзине. Не создаётся напрямую.

Конструктор:  
`constructor(events: IEvents, container: HTMLElement, clickEventName?: string)` - принимает брокер событий, DOM-элемент карточки и название события, которое нужно сгенерировать по клику (передаётся тем, кто создаёт конкретную карточку).

Поля класса:  
`titleElement: HTMLElement` - элемент заголовка товара  
`priceElement: HTMLElement` - элемент цены товара  
`id: string` - идентификатор товара, используется при генерации события клика

Методы класса:  
`set title(value: string)` - записывает заголовок товара  
`set price(value: number | null)` - записывает цену товара, либо текст "Бесценно", если цены нет

События:  
`{clickEventName}` - генерируется по клику на кнопку `.card__button` (если она есть в разметке) либо по клику на всю карточку; передаёт `{ id }` товара

#### Класс CardCatalog extends CardBase
Карточка товара в общей галерее товаров (темплейт `card-catalog`).

Дополнительные поля класса:  
`imageElement: HTMLImageElement` - элемент картинки товара  
`categoryElement: HTMLElement` - элемент категории товара

Дополнительные методы класса:  
`set image(value: string)` - записывает изображение товара  
`set category(value: string)` - записывает текст категории и присваивает соответствующий CSS-класс модификатора цвета из `categoryMap`

#### Класс CardPreview extends CardBase
Карточка товара при подробном просмотре, отображается в модальном окне (темплейт `card-preview`).

Дополнительные поля класса:  
`imageElement: HTMLImageElement` - элемент картинки товара  
`categoryElement: HTMLElement` - элемент категории товара  
`descriptionElement: HTMLElement` - элемент описания товара

Дополнительные методы класса:  
`set image(value: string)` - записывает изображение товара  
`set category(value: string)` - записывает текст категории и присваивает соответствующий CSS-класс модификатора цвета из `categoryMap`  
`set description(value: string)` - записывает текст описания товара

#### Класс CardBasket extends CardBase
Строка товара внутри списка корзины (темплейт `card-basket`).

Дополнительные поля класса:  
`numberPositionElement: HTMLElement` - элемент порядкового номера товара в списке

Дополнительные методы класса:  
`set numberPosition(value: number)` - записывает порядковый номер товара

#### Класс Basket
Отвечает за содержимое корзины — список товаров, общую стоимость и кнопку оформления заказа (темплейт `basket`).

Конструктор:  
`constructor(events: IEvents, container: HTMLElement)` - принимает брокер событий и DOM-элемент корзины.

Поля класса:  
`listElement: HTMLElement` - контейнер списка товаров в корзине  
`priceElement: HTMLElement` - элемент общей стоимости товаров  
`submitButton: HTMLButtonElement` - кнопка "Оформить"

Методы класса:  
`set items(items: HTMLElement[])` - заменяет содержимое списка на переданный массив DOM-элементов карточек (`CardBasket`), либо отображает сообщение о пустой корзине  
`set total(value: number)` - записывает общую стоимость товаров в корзине  
`set valid(value: boolean)` - включает/выключает кнопку "Оформить" в зависимости от того, есть ли товары в корзине

События:  
`order:open` - генерируется по клику на кнопку "Оформить"

---

#### Класс Modal
Отвечает за отображение модального окна. Не может иметь дочерних классов — вся разметка, которая показывается внутри модального окна (карточка, корзина, форма заказа, форма контактов, окно успеха), это самостоятельные компоненты, которые Презентер вставляет в модальное окно через `set content`.

Конструктор:  
`constructor(events: IEvents, container: HTMLElement)` - принимает брокер событий и DOM-элемент модального окна (`#modal-container`).

Поля класса:  
`closeButton: HTMLButtonElement` - кнопка закрытия окна  
`contentElement: HTMLElement` - контейнер для отображаемого содержимого

Методы класса:  
`set content(value: HTMLElement)` - вставляет переданный DOM-элемент внутрь модального окна  
`open(): void` - показывает модальное окно (добавляет класс `modal_active`)  
`close(): void` - скрывает модальное окно (убирает класс `modal_active`) и очищает содержимое

События:  
`modal:close` - генерируется по клику на кнопку закрытия, по клику на затемнённую область вне окна, либо по нажатию клавиши Esc

#### Класс FormBase (абстрактный)
Общий родитель для форм заказа. Содержит функционал, одинаковый для формы выбора оплаты/адреса и формы контактов: отслеживание изменения полей ввода, отображение ошибок валидации, включение/выключение кнопки отправки.

Конструктор:  
`constructor(events: IEvents, container: HTMLFormElement)` - принимает брокер событий и DOM-элемент формы.

Поля класса:  
`submitButton: HTMLButtonElement` - кнопка отправки формы  
`errorsElement: HTMLElement` - элемент для отображения текста ошибки валидации

Методы класса:  
`set valid(value: boolean)` - включает/выключает кнопку отправки формы  
`set errors(value: string)` - записывает текст ошибки валидации

События:  
`{formName}.{field}:change` - генерируется при изменении значения любого поля ввода формы (`{field}` - значение атрибута `name` у `<input>`), передаёт новое значение поля  
`{formName}:submit` - генерируется при отправке формы (по клику на кнопку отправки)

#### Класс Order extends FormBase
Форма выбора способа оплаты и ввода адреса доставки (темплейт `order`).

Дополнительные поля класса:  
`cardButton: HTMLButtonElement` - кнопка выбора оплаты "Онлайн"  
`cashButton: HTMLButtonElement` - кнопка выбора оплаты "При получении"

Дополнительные методы класса:  
`set payment(value: TPayment)` - выделяет активным нужную кнопку способа оплаты

#### Класс Contacts extends FormBase
Форма ввода email и телефона покупателя (темплейт `contacts`). Использует только общую логику родительского класса — отдельных полей и методов не добавляет, поля email и телефон обрабатываются как обычные поля ввода через общий механизм `FormBase`.

Поля класса:  
`descriptionElement: HTMLElement` - элемент с текстом о списанной сумме

События:  
`modal:close` - генерируется по клику на кнопку закрытия окна

### Список всех событий приложения

**События моделей данных** (генерируются при изменении данных):

| Событие | Кто генерирует | Когда генерируется | Данные события |
|---|---|---|---|
| `products:changed` | Products | сохранён новый массив товаров каталога | `{ products: IProduct[] }` |
| `product:selected` | Products | сохранён товар для подробного просмотра | `{ product: IProduct }` |
| `basket:changed` | ShopList | товар добавлен/удалён из корзины, корзина очищена | `{ products: IProduct[] }` |
| `buyer:changed` | Buyer | изменено любое поле покупателя или данные очищены | `{ buyer: IBuyer }` |

**События представлений** (генерируются в ответ на действия пользователя):

| Событие | Кто генерирует | Когда генерируется | Данные события |
|---|---|---|---|
| `basket:open` | Header | клик по кнопке корзины в шапке | - |
| `{clickEventName}` (имя задаётся при создании конкретной карточки) | CardCatalog / CardPreview / CardBasket | клик по карточке или по кнопке `.card__button` внутри неё | `{ id: string }` |
| `order:open` | Basket | клик по кнопке "Оформить" | - |

### Презентер

Логика презентера реализована прямо в `main.ts`, без вынесения в отдельный класс — так как в приложении всего одна страница, и выделять отдельный класс с инверсией зависимостей избыточно для его сложности. Код презентера состоит из подписок на события `events.on(...)`, каждая подписка обрабатывает одно событие и вызывает методы моделей и/или представлений.

**Презентер сам не генерирует ни одного события** — только слушает и реагирует, вызывая методы Model и View напрямую.
